# Learn How to Use Figma for UI/UX Design

## Research & Learn

**What are the core features of Figma, and how is it different from other design tools?**  
Figma is mainly for the visual and interactive side of UX work. It handles screens, components, prototypes, and design systems. The big difference is that it’s cloud‑based and collaborative, so multiple people can work in the same file at the same time. Features like auto‑layout, components, variants, and shared libraries make it easy to keep designs consistent and scalable. Compared to tools like Sketch or Adobe XD, Figma doesn’t need local installs and works across any OS.

**How does Figma support collaboration between designers, developers, and PMs?**  
Everyone can open the same file and see changes instantly. Comments let people leave feedback directly on the design instead of sending screenshots around. Dev Mode gives developers exact specs, CSS values, and assets without needing a separate handoff tool. PMs can follow prototypes to understand flows without needing a designer to walk them through everything.

**What are components, variants, and auto‑layout, and how do they improve design efficiency?**  
Components are reusable pieces like buttons or inputs. Variants let you group different states of a component together, like default, hover, and disabled. Auto‑layout controls spacing, alignment, and resizing so things stay consistent even when text or content changes. Together, they reduce repetitive work and make updates much easier since changing the main component updates every instance.

**How do you share and hand off designs to developers using Figma?**  
Usually by sending a link to the file and making sure Dev Mode is enabled. Developers can inspect spacing, typography, colors, and interactions directly. Exportable assets like icons can be marked for download. Adding notes or annotations helps explain logic or edge cases. Keeping the file organised means developers don’t have to dig around to find the right components.

## Reflection

**How would you organize a design system in Figma to ensure consistency?**  
I’d split it into foundations (colors, typography, spacing), core components (buttons, inputs, cards), and patterns (forms, navigation, modals). Using consistent naming and auto‑layout keeps everything predictable. Variants help group states together so developers don’t have to guess what “hover” or “error” looks like. A clear structure means the team always knows where to find things.

**If a developer needs details about a design component, how would you provide that using Figma?**  
I’d point them to the component in Dev Mode so they can see spacing, padding, and CSS values. If the component has multiple states, I’d make sure they’re included as variants. Notes or annotations help explain behaviour, like when an error message appears or how a dropdown should animate. Keeping everything inside a shared library means they’re always looking at the correct version.

**What challenges might arise when collaborating in Figma, and how can you avoid them?**  
People can accidentally edit or break components if the file isn’t organised. Using naming conventions and locking important layers helps. Another issue is inconsistent design decisions if components aren’t updated together. Keeping a clean design system prevents that. Comments can pile up or get ignored, so resolving them regularly keeps communication clear. Version history helps if someone overwrites something by mistake.
